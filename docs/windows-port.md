# Porting OpenTypist to Windows

This is the brief for building the Windows version. The macOS app in
`Sources/OpenTypist/` is the reference: when in doubt, read the Swift file
named in each section and do the same thing. Everything below was measured or
debugged on the Mac; the numbers are not guesses, so keep them unless you
measure something better on Windows.

## Goal and scope

A Windows 10/11 tray app that does what the Mac app does: grey ghost-text
suggestions after the caret in any app, accepted word by word with Tab,
generated by a local GGUF model through llama.cpp, plus autocorrect, text
replacements (snippets) and personalization. Same models, same prompt format,
same confidence thresholds, same releases page.

## Repository layout

- `windows/` holds the whole Windows app. Do not move or change the Mac code
  (repository root: `Package.swift`, `Sources/`, `Resources/`, `scripts/`)
  except to share assets.
- Reuse, don't copy: `vendor/llama.cpp` (pinned submodule; build it on
  Windows too, same revision) and `Resources/autocorrect/` (Wikipedia list,
  CC BY-SA, with its README).
- Work on a branch (for example `windows`), commit as
  `Claude <noreply@anthropic.com>`, and open a pull request against `main`.

## Recommended stack

| Swift, AppKit, SwiftUI | C# / .NET 8, WPF (tray app, settings window, overlay) |
| llama.cpp static libs (Metal) | `vendor/llama.cpp` built with CMake + MSVC into `llama.dll`; Vulkan backend (works on NVIDIA, AMD and Intel GPUs) with CPU fallback; CUDA optional. | Accessibility (`FocusReader.swift`) | UI Automation (COM `IUIAutomation`): focused element, `TextPattern`/`TextPattern2` for text and caret (`GetCaretRange`), `BoundingRectangles` for the caret rectangle. Fall back to `GetGUIThreadInfo` caret rect for classic Win32 edit controls |

| NSPanel overlay (`OverlayWindow.swift`) | Topmost layered WPF window, `WS_EX_TRANSPARENT \| WS_EX_LAYERED \| WS_EX_NOACTIVATE \| WS_EX_TOOLWINDOW`; per-monitor DPI v2 awareness |

## Behavior to replicate

### Prompt (`Suggestion.swift`, `PromptBuilder`)

Base (non-chat) models continue text, so the prompt is a plain document. The
header goes first, ordered from least to most often changing, so the KV cache
keeps it:

```
About me:
<profile>

Examples of things I've written in <App>:
"<sample>"
"<sample>"

Application: <App>
Window: <window title, max 120 chars>
Visible on screen:
<OCR text, max 900 chars>

Text being written:
<text before the caret, last 1200 chars, starting at a word boundary>
```

Each block is omitted when empty. A bug where the header was overwritten
instead of appended silently dropped the profile once; test that the profile
really reaches the prompt.

- If the text ends with spaces, strip them from the prompt; the generated text
  must then start with a space, which is dropped (no output, no suggestion).
- If the text ends with a letter, use **token healing**: remove the last prompt
  token and constrain the first generated token to start with its bytes. This
  is what turns "I am very in" into "terested in", the most used feature.

### Generation (`LlamaEngine.swift`)

- Context 4096, batch 512, `swa_full = true` (Gemma uses sliding-window
  attention; without it the cache can't be trimmed to a prefix), all layers on
  the GPU.
- Greedy decoding. Keep the token list in the KV cache and reuse the longest
  common prefix between requests, so a keystroke costs a few tokens.
- Max tokens / words by length setting: short 10 / 3, medium 20 / 7,
  long 36 / 15. Stop at a newline.
- Cancel a running generation as soon as a newer keystroke arrives.
- Stream: show the suggestion once its first word is complete and grow it
  word by word (`streamingText`); the first word is ready in about half the
  time of the full suggestion.
- Gemma 4 E2B is downloaded as Q4_0 (same measured quality as Q4_K_M, a little
  faster on GPUs); measure Q4_0 vs Q4_K_M on Windows GPUs too, since the best
  format differs by backend.
- Free the model before the process exits (ggml's GPU backend can assert
  otherwise).

### Confidence filter (`confidentText`, `ConfidenceLevel` in `Settings.swift`)

Every generated token carries its probability (softmax of the chosen logit;
for the healed first token, normalized over the allowed candidates). The
suggestion ends at the first token below the threshold; if that token would
have continued the current word, the half-finished word is dropped too.
Tokens that finish a half-typed word use a looser threshold.

| Level | Words after the current one | Finishing the current word |
| --- | --- | --- |
| More suggestions | 0.12 | 0.06 |
| Balanced (default) | 0.25 | 0.10 |
| Fewer, more accurate | 0.45 | 0.15 |

Measured with `OpenTypist --calibrate` on Gemma 4 E2B: Balanced shows a
suggestion 74% of the time with 50% of suggested words right (no filter: 91%
and 26%); half-typed words are finished correctly 87–92% of the time.

### When to suggest (`CompletionController.swift`)

- Refresh 60 ms after a keystroke; never on clicks alone.
- Skip: password fields, apps on the disabled list (terminals, IDEs, password
  managers by default), text selected, fewer than 3 characters, caret right
  after a newline, caret inside a word.
- Mid-line (text after the caret): use the short length, show the suggestion
  in a small card just below the line (inline text would cover what follows),
  and trim it so it leads into the following text instead of repeating it
  (`fitBefore`: "terested in this job" before " this job" → "terested in").
- While the user types exactly what is suggested, keep the suggestion and
  shrink it; any other key hides it.
- Accept: next word (default Tab, includes the following space), whole
  suggestion (default Shift+Tab), Esc dismisses. Keys are configurable,
  globally and per app; refuse letters, digits, Space, Delete and Esc without
  Ctrl/Alt/Win. Optionally add a space after finishing a suggestion.
- After accepting, wait until the field actually contains the inserted text
  before reading it again (apps apply synthetic input asynchronously).

### Ghost text (`OverlayWindow.swift`)

Use the field's own font and a faded (45% alpha) version of its text color
when UI Automation reports them, otherwise grey. Wrap like real text: the
right edge is the field's right edge minus the same padding it has on the
left, or earlier if hit-testing along the caret's line finds an element that
isn't part of the field (a send or microphone button); continuation lines
start at the x of the line's first character. Single-line fields don't wrap.
Show a small hint with the accept key after the text.

### Autocorrect (`Autocorrector.swift`, `AutocorrectRules.swift`)

- Track recently typed characters from the keyboard hook (reset on clicks,
  arrows, shortcuts, app switches).
- On an ending character (space, Enter, Tab, `-()[]{}:;"/\,.?!`), look the
  text up in the lists: swallow the ending key, delete the typo, type the fix,
  replay the ending key. Delete right afterwards undoes it and adds the word to
  the never-correct list. Match the typed capitalization (`Teh` → `The`).
- The AutoHotkey importer understands `::typo::fix`, options `*` (instant),
  `?` (inside words), `C` (case-sensitive), `B0`, multi-word triggers and
  exception entries (`::design::`). AHK files are often Windows-1252.
- A list entry whose typo is also a real word ("loosing"), entries with
  several fixes ("achive" → achieve or archive), and words the spell checker
  doesn't know go to the model 60 ms later: score each candidate's
  log-probability after the context, subtract 2.0 × a keyboard typo cost
  (insert/delete 0.8, neighbouring key 0.8, other key 1.5, swap 0.6), and fix
  only if the best beats the typed word by 0 (known misspelling), 2.5
  (unknown word) or 1.5 (real word, no typo cost). Never touch capitalized
  words mid-sentence or ALL-CAPS words. Re-check the field before replacing.

### Text replacements (`TextReplacements.swift`)

User snippets (shortcut → text, inserted exactly, line breaks as Shift+Enter),
checked before autocorrect, undoable with Delete. Windows has no system-wide
list like macOS's, so snippets only (optionally import a plain
`shortcut->text` file).

### Personalization (`Personalization.swift`, `WritingSamples.swift`)

- The profile is a first-person note at the top of every prompt. Base models
  follow facts ("I sign emails 'Cheers, Alex'"), not instructions.
- Learn only from typed keys, never screen text: names typed mid-sentence,
  words the spell checker doesn't know (3 uses to count, ties alphabetical so
  lines don't flip), US vs British spelling (5 uses, 75%), greeting and
  sign-off lines, per-app lowercase style.
- Learned facts are appended as lines at the end of the profile. A line the
  user edits or deletes makes that topic theirs. Lock, "ask me first", and a
  restorable history.
- Writing samples are opt-in: keep what was typed in a field when the user
  leaves it or it clears (message sent), strip card numbers and long tokens,
  max 600 characters, 400 samples; use up to 3 recent samples from the same
  app (prefer the same window title) in the prompt.
- Everything personal is encrypted at rest.

### Models (`ModelCatalog.swift`)

Same catalog, same pinned URLs and SHA-256 checksums; nothing downloads until
the user picks a model. Recommend by RAM (and on Windows, by GPU memory):
Qwen 3 1.7B under 12 GB, Gemma 4 E2B under 24 GB, Gemma 4 E4B from 24–32 GB,
Gemma 4 26B A4B from 64 GB. On CPU-only machines prefer the small models.

### Memory & battery

Optional unload after 5–120 minutes without typing (reload on the next
keystroke) and, on battery or in battery saver: keep going, use the smaller
model, or pause.

## Windows-specific traps to plan for

- **Elevated windows.** A normal process can't hook or send input to apps
  running as administrator (UIPI). Detect it and stay quiet there rather than
  half-working.
- **UI Automation varies by app.** Win32 edit controls, WinUI/WPF, Office,
  Chromium/Electron (Chrome, Edge, Slack, Discord, VS Code) and Firefox all
  report text and caret differently. Test each family; log why a field was
  skipped (the Mac app's "Last check" diagnostics were essential).
- **Keyboard layouts and IMEs.** Use `ToUnicodeEx` for typed characters, and
  stay out of the way while an IME composition is active.
- **DPI.** Caret rectangles from UIA are in physical pixels; the overlay must
  be per-monitor DPI aware.
- **Hook timeouts.** Windows silently removes a low-level hook that takes too
  long; never do UIA or model work inside the hook callback.
- **SmartScreen.** Unsigned builds show "Windows protected your PC". Say so in
  the release notes until there is a code-signing certificate.

## Build, test, release

- `windows/` should build with one script (CMake for llama.cpp, then
  `dotnet publish`), producing a self-contained x64 app (ARM64 later).
- Port the Mac `--selftest` idea: a command that loads the model, runs sample
  prompts, prints suggestions and per-keystroke latency, and checks the pure
  logic (prompt, confidence cut, fitBefore, autocorrect rules, AHK parsing).
- CI: add a `windows-latest` job to `.github/workflows/ci.yml` (build + test
  without a model). Releases: add a Windows job to `release.yml` that runs
  after the macOS job and uploads `OpenTypist-<version>-win-x64` assets to the
  same GitHub release (`gh release upload`). Keep the Mac updater's asset
  names (`.dmg`, `.dmg.sha256`) unchanged.

## Suggested phases

1. **Engine and ghost text**: llama.dll + wrapper, model download, prompt,
   confidence filter, token healing; UIA reading; keyboard hook; overlay; Tab
   and Shift+Tab; tray icon; minimal settings. Done when suggestions work in
   Notepad, Word, Chrome/Edge text areas and Slack or Discord.
2. **Autocorrect, snippets, accept keys per app, mid-line card, wrapping.**
3. **Personalization, screen context (OCR), memory and battery options,
   stats, updater, CI and release integration.**
